The stack

Everything between the file
and the first token.

TeaCat implements the whole pipeline itself: GGUF parsing, quantization kernels, tokenizers, attention, sampling, storage and HTTP. No llama.cpp, no cgo, no black boxes.

From bytes to tokens, in one binary

Load a GGUF file, parse its metadata, expand F16 weights once, run quantized matvecs through every layer, then sample the next token. Every step is plain, readable Go in this repository.

From-scratch engine

RMSNorm, RoPE, grouped-query attention with a KV cache, SwiGLU feed-forward layers and a sampler. Written directly against Go slices — no cgo, no bindings.

GQAKV cacheRoPESwiGLU
$ go build ./...
✓ windows · linux · darwin

GGUF, ready for real models

Reads GGUF v2 and v3 with alignment handling and a complete tensor table. F32, F16 and BF16 are supported alongside the quantized formats most local models ship with.

Q4_0Q5_0Q8_0Q2–Q6_KIQ4_NL+8 more

Tokenizers that match the model

SentencePiece/unigram and byte-level BPE are rebuilt from GGUF metadata. Chat templates for ChatML, Llama 3, Llama 2, Phi-3, Gemma and Command-R are detected automatically.

SPMbyte-BPEChatMLLlama 3

Sampling you control

Temperature, top-k, top-p, min-p, repetition penalty, seeds and greedy mode. Tune it in the CLI, the API or the dashboard.

A real model store

Content-addressed blobs and JSON manifests under ~/.teacat. Pull from the Ollama registry with SHA-256 verification, import a local GGUF, or fetch a direct URL.

Two APIs, one port

Ollama-compatible endpoints and OpenAI-compatible chat completions, both streaming. Point an existing client at 127.0.0.1:11434 and it just works.

The dashboard

A local UI that
ships inside the binary.

Run teacat ui and the browser opens. Chat, pull models, delete them, tune sampling and copy API endpoints — all against localhost.

  • Streaming chat with a stop button and live tokens/sec, parsed straight from the local NDJSON stream.
  • Model library with size, parameter count and quantization, plus one-click delete.
  • Pull progress for any Ollama-registry model, with checksum-verified blobs.
  • Sampling controls for system prompt, temperature, top-p, top-k and max tokens.
  • Embedded and offline — one HTML file compiled into Go, no CDN and no extra install.

How it works

Four steps from download
to a streaming answer.

No daemon, no container, no cloud round-trip. The same process downloads the model, loads the weights and generates tokens.

Pull

Fetch a model from the Ollama registry, a direct GGUF URL or a local file. Every blob is checked against its SHA-256 digest.

teacat pull qwen2.5:0.5b

Load

Read the GGUF header and tensor table, expand F16/BF16 weights once, and keep quantized tensors packed for fast matvecs.

gguf.Open → model.Load

Prefill

Tokenize the prompt with the model's own tokenizer and chat template, then run every prompt token through all layers to fill the KV cache.

prefill → KV cache

Stream

Sample a token, feed it back through the network and emit text as UTF-8. The dashboard, CLI, Ollama and OpenAI clients all see it live.

NDJSON · SSE

Performance

Honest numbers,
not promises.

TeaCat is a scalar, pure-Go CPU engine. It trades raw throughput for a stack you can read end to end. These are measured numbers, not targets.

SmolLM2 135M F16 expanded to F32
~14 tok/s
prompt ~17 tok/s · 8 CPU threads
Qwen2.5 0.5B Q5_0-mixed quantized
~2 tok/s
prompt ~2.5 tok/s · same machine

Why it is slower than llama.cpp

llama.cpp uses hand-tuned SIMD and assembly kernels. TeaCat uses straightforward Go loops so the entire engine stays auditable. For small models it is comfortable; for large ones it is a reading project, not a speed record.

  • Threads8
  • AccelerationCPU · scalar Go
  • GPU offloadnot yet
